## What cig should carry away

- The back end is a four-stage pipeline per function, driven by one function in `compile.rs`: lower (backward scan builds VCode), regalloc (`regalloc2::run_with_ctx`), optional symbolic-checker, emit (forward scan writes bytes through `MachBuffer`). Stage C calls this function per function; nothing in the pipeline reaches the call graph (entries 1, 3).
- Instruction selection is a backward pass with "instruction colors": a merge of a producer into its single-user consumer is allowed only when no side-effecting instruction sits between them in the block, which `has_lowering_side_effect` labels (loads included, to respect the memory model). cig's `Pure` / `MayRaise` / `Effect` / `Step` classes already carry this discipline (entry 1).
- SystemV returns two registers (`rax`, `rdx`), `Tail` up to eight (`rax, rcx, rdx, rsi, rdi, r8, r9, r10`). cig's value today is three machine words (24 bytes, `Rc<str>` as a fat pointer); cig-compile#35 plans a tagged 16-byte (two-word) value, and a NaN-boxed 8-byte (one-word) value is the alternative. cig-compile#32's value ABI assumes the 16-byte case. A call that returns value-plus-status under 16 bytes wants three registers (`SystemV` with `enable_llvm_abi_extensions` on x86-64 fits); under 24 bytes wants four (`SystemV` extended is one short, so `Tail` is the fit); under 8 bytes wants two (plain `SystemV` fits). Aarch64 returns in `x0..x7` under `SystemV`, `Tail` and `AppleAarch64`, so each case fits on aarch64 (entry 7).
- regalloc2 exposes two algorithms. Ion is a backtracking allocator with live ranges, bundles, splitting and eviction, bounded below by a minimal-bundle weight that guarantees termination; Fastalloc is a single-pass reverse-linear-scan allocator that trades code quality for allocation time. cig would pick between them per `opt_level` (no such mapping exists today, cig has no Cranelift dependency), through Cranelift's `regalloc_algorithm` flag (entries 12, 13).
- regalloc2 ships a symbolic dataflow checker that proves each inserted move and spill preserves the input SSA's dataflow; it is a correctness artefact, not a debug aid, and runs when `regalloc_checker` is set. cig's differential suite (#39) uses this as one of its two gates on every stage-C build (entry 14).
- `MachBuffer` is a single-pass emitter with on-the-fly peephole branch simplification, out-of-range veneer and constant-pool islands scheduled by deadlines, label aliasing for empty branch-threading blocks, and a `LABEL_LIST_THRESHOLD` of 100 that bounds quadratic worst-case behavior. Side-tables (relocations, traps, call sites, source locations, user stack maps, exception handlers, debug tags, unwind) are recorded beside the bytes, keyed on code offsets after the buffer finalizes (entries 4, 5).
- Cranelift makes no memory writable and executable at the same time: its JIT back end allocates pages read-write, writes the bytes, then calls `set_readable_and_executable` (which issues `mprotect` through the `region` crate and optionally applies BTI). This satisfies cig's rule 8 directly; stage C would write an object file through `cranelift-object`, and cig-cherry's JIT would use the same pattern (entries 17, 18).
- The back end is configured by named settings (`enable_pinned_reg`, `preserve_frame_pointers`, `enable_probestack`, `probestack_strategy`, `use_bti`, `sign_return_address`, `enable_heap_access_spectre_mitigation`, `enable_nan_canonicalization`, `unwind_info`, `opt_level`), each a single-bit or small-enum knob; cig's compiler-flag table maps one-to-one onto these at stage C (entries 10, 19).

## Design points

### 1. Lowering is a backward scan with instruction colors

- **What it does, and why.** `Lower::lower_clif_block` walks each CLIF block in reverse (`self.f.layout.block_insts(block).rev()`) and emits lowered machine-code instructions in reverse VCode order. Before the walk, every CLIF instruction is assigned an `InstColor` by scanning each block forward and incrementing the color on any instruction for which `has_lowering_side_effect` returns true. Two instructions share a color exactly when no side-effecting instruction sits between them; a load counts as side-effecting here "to avoid subtle questions w.r.t. the memory model", so a load may not be moved across a store. When lowering a user, the back end may try to merge a producer in by calling `get_input_as_source_or_const`: the result has `InputSourceInst::UniqueUse` or `Use`, driven by `value_ir_uses` (a coarsened "zero / one / many" count, called `ValueUseState` in the source) computed up front and propagated as `Multiple` is "contagious".
- **For cig: adapt.** By rule 1 (burns never move) and rule 5 (identical behavior on every engine): CIR's `Class { Pure, MayRaise, Effect, Step }` in `cig-script/src/lower/cir/ir.rs` is the same discipline. `Pure` is Cranelift's "non-side-effecting", `Effect` and `Step` are side-effecting (and `Step` carries the budget tick, which stage C would lower as an opaque skeleton call), and `MayRaise` is side-effecting unless the verifier's `T4` proves the raise is impossible. Stage C (not built today) would lower CIR into CLIF one block at a time, forward (CIR is structured SSA with named blocks), so the backward pass is Cranelift's internal detail; the use-count analysis is what stage C would expose to lowering, so cig would record uses on CIR `ValueId` the same way.
- **What would decide it.** Decided by rules 1 and 5.
- **Feeds.** cig-compile#32; decision (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/machinst/lower.rs` (`Lower`, `lower_clif_block`, `InstColor`, `ValueUseState`, `InputSourceInst`, `has_lowering_side_effect`, `must_lower_even_if_unused`); `wasmtime-v50.0.1/cranelift/codegen/src/inst_predicates.rs` (`has_lowering_side_effect`, `must_lower_even_if_unused`); `cig-script/src/lower/cir/ir.rs` (`Class`, `ValueId`); `cig-script/src/lower/cir/verify.rs` (`T4`).

### 2. The ISLE lowering back end: pattern-matched rules per target

- **What it does, and why.** Each ISA has a `lower.isle` rule file (for x86-64: `isa/x64/lower.isle` plus the term definitions in `isa/x64/inst.isle`) that matches on CLIF opcodes and produces machine instructions. The prelude term `lower` is the entry point: for every `Inst`, the ISLE-generated constructor is called with the `Lower` context; a `None` result means no rule applied and `lower_clif_block` returns `CodegenError::Unsupported`. The lowering context exposes `put_in_reg`, `put_in_regs`, `put_in_xmm`, `sink_inst`, `use_input_reg` and the rest to rules; each use that the rule consumes is reported through this trait, which is what maintains the lowered use-count and lets the color analysis decide whether a merge is legal. The whole prelude lives in `prelude_lower.isle`, shared across every target, and defines types, constructor shells, and the glue term `output_rets`.
- **For cig: adapt.** By rule 1 (burns never move) and rule 5 (identical behavior): rules with overlap-checking at compile time make the "what codegen does" smaller than hand-written code (cig's VM has 73 opcodes in `cig-script/crates/cig-bytecode/src/opcode.rs`, and stage C would face a similar order), and the same overlap check catches a pass bug at build time rather than at runtime. cig's form: a single lower.isle file over CIR temporaries, with cig's own class system plumbed through the prelude, housed in a new `cig-compile/src/` module. The rules are not a fit until CIR's grammar stops changing (same observation as the mid-end study); until then, hand-written per-op match code is cheaper.
- **What would decide it.** Not measured yet: the LOC in `lower.rs` after a rewrite of ten opcodes to rules against the same ten opcodes as code, on the test machine, with golden tests holding.
- **Feeds.** cig-compile#32; decision (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/isa/x64/lower.isle`; `wasmtime-v50.0.1/cranelift/codegen/src/isa/x64/inst.isle`; `wasmtime-v50.0.1/cranelift/codegen/src/prelude_lower.isle`; `wasmtime-v50.0.1/cranelift/codegen/src/machinst/isle.rs` (`isle_lower_prelude_methods`); `cig-script/crates/cig-bytecode/src/opcode.rs`; `cig-script/src/lower/cir/ir.rs`.

### 3. One function at a time: `compile` drives lower-regalloc-check-emit, with edge blocks materialised

- **What it does, and why.** `cranelift/codegen/src/machinst/compile.rs` is 95 lines: `compile` takes a `Function`, a `DominatorTree`, a reusable `regalloc2::Ctx`, the `TargetIsa` and `ControlPlane`, builds `BlockLoweringOrder`, constructs the `Lower` context, runs lowering under `timing::vcode_lower`, calls `regalloc2::run_with_ctx` under `timing::regalloc` with `Algorithm::Ion` or `Algorithm::Fastalloc` depending on the `regalloc_algorithm` flag, optionally runs the symbolic checker under `timing::regalloc_checker`, and returns `VCode`. Emission is downstream in `VCode::emit` (`vcode.rs`), driven by the caller through `Context::compile`. `BlockLoweringOrder::new` computes a reverse-postorder over a CFG augmented with implicit edge blocks (every CFG edge is `LoweredBlock::Orig` or `LoweredBlock::CriticalEdge`); the edge blocks give lowering a place to put block-parameter copies, which is what satisfies regalloc2's rule that the CFG has no critical edges. Cold blocks are not reordered in the main sequence (the order must respect RPO) but are tracked in a separate `cold_blocks` set and sunk at emission time by `MachBuffer` so hot blocks stay contiguous. The whole function-level interface is per-function: there is no module-wide state, so stage C could parallelize across functions by sharing only the `TargetIsa`.
- **For cig: take.** By rule 8 (reproducible, signable) and rule 10 (ahead of time by default): the per-function boundary is the smallest unit of compilation and the right one for cig. Stage C's inner loop is this function, run per CIR function with a per-thread regalloc context. The function signature (no module state, reusable allocator context) is what lets stage C and cig-cherry share the generator by crate boundary (decision (e)). CIR has structured blocks, so the CIR-to-CLIF mapping is one-to-one with edge blocks only around `if`, `try` and loops; the sunk-cold-blocks optimization is allowed because it only moves blocks in layout, not in execution.
- **What would decide it.** Decided by rules 8 and 10.
- **Feeds.** cig-compile#32, #37; decision (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/machinst/compile.rs` (`compile`, `vcode_lower`, `regalloc`, `regalloc_checker`); `wasmtime-v50.0.1/cranelift/codegen/src/machinst/vcode.rs` (`VCode`, `VCodeBuilder`); `wasmtime-v50.0.1/cranelift/codegen/src/machinst/blockorder.rs` (`BlockLoweringOrder`, `LoweredBlock`, `CriticalEdge`, `cold_blocks`); `regalloc2-v0.15.3/doc/GENERAL.md` (`CFG`, `critical edges`); `cig-script/src/lower/cir/ir.rs` (`Block`).

### 4. `MachBuffer`: single-pass emission with peephole simplification, veneers and islands

- **What it does, and why.** `MachBuffer` is a byte sink with on-the-fly label fixups. Forward branches are emitted with optimistic zero offsets and a fixup is recorded; when the label is bound, the fixup is applied and the branch patched. Four peephole rules clean up branches as they are emitted: a branch whose target is its own fallthrough is removed; an unconditional branch that starts at a label simply redirects that label (branch threading); a conditional branch whose target is an unconditional's fallthrough is inverted; and an unconditional following another unconditional, with labels redirected, is removed. A `LABEL_LIST_THRESHOLD` of 100 caps the "labels bound at this offset" list and aborts the optimization conservatively past that bound to keep worst-case behavior linear in code size. For out-of-range references (on aarch64 a conditional branch reaches about 1 MB, an unconditional 128 MB), `emit_island` writes a "veneer" (a longer-range branch to the real target) and a constant-pool island at a safe point between blocks, with a jump around the island so execution does not fall into it. The central invariant stated in the doc comment is `worst_case_end_of_island(0) <= soonest_deadline`. The implementation splits fixups into a pending list (editable by peephole rules) and a `BinaryHeap` final list, "to avoid quadratic island behavior".
- **For cig: take.** By rule 1 (burns never move) and rule 8 (reproducible, signable): peephole rules on branches only edit code shape, never move an effect across a boundary; veneers and islands are a correctness feature on aarch64 that stage C and cig-cherry both need. cig has no equivalent today (no Cranelift dependency, no native code); once stage C is built, it would use `MachBuffer` directly as the sink.
- **What would decide it.** Not measured yet: aarch64 build time of `orchestrate.cig` with the default island policy against a forced one-island-per-block policy, on the test machine.
- **Feeds.** cig-compile#32, #41; decisions (d), (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/machinst/buffer.rs` (`MachBuffer`, `LABEL_LIST_THRESHOLD`, `latest_branches`, `label_aliases`, `emit_island`, `emit_island_maybe_forced`, `ForceVeneers`, `finish_emission_maybe_forcing_veneers`); `wasmtime-v50.0.1/cranelift/codegen/src/machinst/vcode.rs` (`VCode`).

### 5. Side-tables beside the bytes: relocations, traps, call sites, srclocs

- **What it does, and why.** `MachBuffer` records, in parallel with the emitted bytes, the auxiliary data a code consumer needs. `add_reloc` (and `add_reloc_at_offset`) records an external relocation with its `Reloc` kind and `RelocTarget`; `add_trap` records a `TrapCode` at the current offset; `add_call_site` records a call-site offset so an unwinder can walk through; `start_srcloc` and `end_srcloc` bracket a region of code with its CLIF-level `RelSourceLoc`, and `get_srclocs_sorted` returns the merged list after finalize. `MachBufferFinalized` holds the final `relocs`, `traps`, `call_sites`, `srclocs`, `exception_handlers`, `user_stack_maps` (`SmallVec<[(CodeOffset, u32, ir::UserStackMap); 8]>`) and `MachBufferFrameLayout`. All records key on code offsets; the tables are the interface a loader, a debugger or an unwinder reads. The x64 lowered instruction is emitted through `cranelift-assembler-x64`'s `enum Inst<R:Registers>` (one variant per encoding), fuzzed against a known-good disassembler for roundtrip.
- **For cig: take.** By rule 2 (errors happen at the same place) and rule 8 (reproducible, signable): `srclocs` are what would let stage C put `E503`, `E515` and `E701` on the same file:line:col the tree-walker does, by lowering each CIR `Instr::span` into `start_srcloc`/`end_srcloc` calls around the lowered range. `relocs`, `call_sites`, `traps` and `exception_handlers` are what the object writer and the runtime linker consume. cig's form: stage C would write the finalized `MachBufferFinalized` straight into `cranelift-object`, and cig-cherry's loader would read the same tables from an in-memory buffer; neither reinvents the assembler.
- **What would decide it.** Decided by rules 2 and 8.
- **Feeds.** cig-compile#32, #38; decision (d).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/machinst/buffer.rs` (`add_reloc`, `add_reloc_at_offset`, `add_trap`, `add_call_site`, `start_srcloc`, `end_srcloc`, `get_srclocs_sorted`, `MachBufferFinalized`); `wasmtime-v50.0.1/cranelift/codegen/src/ir/sourceloc.rs` (`SourceLoc`, `RelSourceLoc`); `wasmtime-v50.0.1/cranelift/codegen/src/binemit` (`Reloc`); `wasmtime-v50.0.1/cranelift/assembler-x64/README.md`; `wasmtime-v50.0.1/cranelift/assembler-x64/src/lib.rs`; `cig-script/src/lower/cir/ir.rs` (`Instr`).

### 6. ABI framework: `ABIMachineSpec` and the per-target `MachineEnv`

- **What it does, and why.** `machinst/abi.rs` is a 2,676-line generic ABI implementation. It defines the trait `ABIMachineSpec` that each ISA implements (`X64ABIMachineSpec`, `AArch64MachineDeps`): the trait says how `compute_arg_locs` places arguments and returns into `ABIArg::Slots` of `ABIArgSlot::Reg` or `ABIArgSlot::Stack`, how `gen_probestack` and `gen_inline_probestack` emit stack-overflow probes, how clobbers are identified per calling convention, and how spills and reloads are generated. `Callee` is the per-function ABI state. The stack layout is documented at the top of the file: caller frames, stack args, return address, pushed FP, clobbered callee-saves, spill slots, stack slots, outgoing-args area, all SP-relative.

  Each ISA builds a `regalloc2::MachineEnv` naming `preferred_regs_by_class` (caller-saved on SysV: `rsi, rdi, rax, rcx, rdx, r8, r9, r10, r11` and XMM0..XMM7), `non_preferred_regs_by_class` (callee-saved on SysV: `rbx, r12, r13, r14`, plus `r15` when `enable_pinned_reg` is off, and XMM8..XMM15), `scratch_by_class` (`[None, None, None]` on x86-64: regalloc2 will auto-spill one to produce a scratch; see `GENERAL.md`), and `fixed_stack_slots` (empty on x86-64). The clobber sets `SYSV_CLOBBERS`, `WINDOWS_CLOBBERS`, `ALL_CLOBBERS` are pre-built `PRegSet` constants.
- **For cig: take.** By rule 10 (ahead of time by default) and decision (a): the ABI is shared ground between stage C's AOT and cig-cherry's JIT; the trait abstraction means an aarch64 build and an x86-64 build share this file. cig would use the stock SysV env with `enable_pinned_reg=true` (pinning `r15`), and the stock AAPCS env with `x28` pinned on aarch64, once stage C is built; cig would not reinvent `MachineEnv`.
- **What would decide it.** Decided by rules 1 and 10.
- **Feeds.** cig-compile#32, #41; decisions (a), (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/machinst/abi.rs` (`ABIMachineSpec`, `Callee`, `ABIArg`, `ABIArgSlot`, `compute_arg_locs`, `gen_probestack`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/x64/abi.rs` (`X64ABIMachineSpec`, `create_reg_env_systemv`, `SYSV_CLOBBERS`, `WINDOWS_CLOBBERS`, `ALL_CLOBBERS`, `preferred_regs_by_class`, `non_preferred_regs_by_class`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/aarch64/abi.rs` (`AArch64MachineDeps`); `regalloc2-v0.15.3/src/lib.rs` (`MachineEnv`, `scratch_by_class`, `fixed_stack_slots`); `regalloc2-v0.15.3/doc/GENERAL.md` (`scratch register`); `cig-script/src/value.rs`.

### 7. Calling conventions, cig's value size, and the sret fallback

- **What it does, and why.** `isa/call_conv.rs` enumerates the conventions Cranelift knows: `Fast` ("best performance, not ABI-stable"), `Tail` ("supports tail calls, not ABI-stable except for exception payload registers"), `SystemV`, `WindowsFastcall`, `AppleAarch64`, `Probestack`, `Winch` ("internal calling convention for Winch-generated functions"), `PreserveAll` (clobbers no registers).

  Return-register tables for x86-64 (`get_intreg_for_retval`): `Fast`, `SystemV` and `PreserveAll` share one arm and return `rax`, `rdx`, with `rcx` as a third register only when `enable_llvm_abi_extensions` is set (`isa/x64/abi.rs:1087-1091`); `WindowsFastcall` returns `rax`, `rdx`; `Tail` returns up to eight regs in `rax, rcx, rdx, rsi, rdi, r8, r9, r10` (the comments at `isa/x64/abi.rs:1082-1084` state that `r11` is reserved as scratch and part of the clobber set, and `r15` is reserved as a scratch); `Winch` returns only the last value in `rax`. On aarch64, "we may return values in 8 registers for V128 and I64 registers independently" (`isa/aarch64/abi.rs`, `compute_arg_locs`), using `x0..x7` and `v0..v7`. The x86-64 `exception_payload_regs` function returns the two-register `PAYLOAD_REGS` (`rax`, `rdx`) only for `SystemV | Tail | PreserveAll` and the empty slice for every other variant (`isa/x64/abi.rs:979-987`); `AppleAarch64` is unreachable on x86-64 (`unreachable!()` at `isa/x64/abi.rs:1101`). The convention-level `exception_payload_types` (`isa/call_conv.rs:122-133`) is platform-agnostic and covers the four conventions `Tail`, `SystemV`, `PreserveAll`, `AppleAarch64`.

  When a signature returns more values than the convention's registers hold, Cranelift falls back to a hidden return-area pointer: a `StructReturn` argument whose value is a caller-allocated buffer, filled by the callee, and the callee returns the pointer again (`Callee::init_retval_area`, `gen_retval_area_setup`). The implicit form `enable_multi_ret_implicit_sret` is deprecated; the recommended path is an explicit `ArgumentPurpose::StructReturn`.
- **For cig: adapt.** By decision (a) and rule 5: cig's `Value` is today three machine words (24 bytes, because `Rc<str>` is a fat pointer, per `cig-script/src/value.rs`'s `enum Value`). cig-compile#35 plans a tagged 16-byte value (two words, tag + payload) and cig-compile#32's value ABI assumes it; a NaN-boxed 8-byte value is the alternative. Taking the planned 16-byte value as the main case: a call that returns value-plus-status wants three registers; on x86-64, `SystemV` (two regs) is one register short, `SystemV` with `enable_llvm_abi_extensions` (three regs, `rax, rdx, rcx`) fits, `Tail` (eight regs) also fits and leaves room for per-call step budget and journal position (decision (d)). For today's 24-byte value: value-plus-status wants four registers; `SystemV` extended (three) is one short, so `Tail` is the only in-register fit on x86-64. For a one-word NaN-boxed value: value-plus-status wants two registers and plain `SystemV` suffices. On aarch64, all three cases fit under `SystemV`, `Tail` or `AppleAarch64` (eight returns each). Stage C would set the function's `ir::Signature::call_conv` to `CallConv::Tail` for cig-internal calls once stage C is built. For the rare cases that exceed the convention's cap, stage C would pass an explicit result buffer rather than relying on the deprecated implicit sret.
- **What would decide it.** Not measured yet: on `orchestrate.cig` and `mandel.cig` (once stage C is built), the cost of spilling the status byte through memory with `SystemV` (two regs) against returning it in `rcx` under `enable_llvm_abi_extensions` or in a higher reg under `Tail`, for whichever value size decision (a) settles on, on the test machine.
- **Feeds.** cig-compile#32, #35; decisions (a), (d).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/isa/call_conv.rs` (`CallConv`, `Tail`, `SystemV`, `WindowsFastcall`, `Fast`, `Winch`, `PreserveAll`, `AppleAarch64`, `supports_tail_calls`, `supports_exceptions`, `exception_payload_types`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/x64/abi.rs` (`get_intreg_for_retval`, `get_fltreg_for_retval`, `exception_payload_regs`, `PAYLOAD_REGS`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/aarch64/abi.rs` (`compute_arg_locs`); `wasmtime-v50.0.1/cranelift/codegen/meta/src/shared/settings.rs` (`enable_multi_ret_implicit_sret`, `enable_llvm_abi_extensions`); `wasmtime-v50.0.1/cranelift/codegen/src/machinst/abi.rs` (`StructReturn`, `init_retval_area`, `gen_retval_area_setup`); `cig-script/src/value.rs` (`Value`).

### 8. Tail calls: `return_call` and the `Tail` convention

- **What it does, and why.** `CallConv::supports_tail_calls` returns true for `Tail` and only `Tail`. The IR instruction is `return_call` (and `return_call_indirect`); the lower side is `gen_return_call_args` on `Lower`, which goes through `Callee::gen_call_args` with `is_tail_call = true`. The callee under `Tail` pops its own stack arguments before returning, which is what makes tail-call sites small enough to re-use the caller's stack frame area. The exception-payload registers on `Tail` are `rax, rdx` on x86-64 and `x0, x1` on aarch64 ("ABI-stable except for exception payload registers", per the enum's doc).
- **For cig: adapt.** By rule 1 (burns never move) and rule 10 (ahead of time by default): cig has no explicit tail-call opcode in the VM today, but structured loops that take the form of self-tail-calls at the source level (recursion over a list) would benefit from a tail-call lowering at stage C to avoid growing the stack. The ABI constraint is: tail calls work only when caller and callee share the `Tail` convention, so cig's internal calls (CIR function to CIR function) would all use `Tail`; calls to the runtime and to libc would use `SystemV` or the platform default. cig's form: a lowering pass at CIR would tag self-recursive calls in tail position (last operation before `Ret`), and stage C would lower them to `return_call` iff caller and callee are both CIR functions.
- **What would decide it.** Not measured yet: `fib.cig` recursion depth with and without tail-call lowering at stage C, on the test machine.
- **Feeds.** cig-compile#32; decision (e).

### 9. `try_call` and exception tables

- **What it does, and why.** `try_call` and `try_call_indirect` are CLIF instructions that call a function and name a block destination for every exception tag the callee may raise (plus a "normal" destination). `ExceptionTableData` in `ir/exception_table.rs` holds, for one call site, a `Vec<BlockCall>` of targets plus a `Vec<InternalExceptionTableItem>` of (tag or context-value, target-index) tuples and the `SigRef` of the callee. The back end records an entry in `MachBuffer::exception_handlers` per catch destination. The convention's `exception_payload_types` (`isa/call_conv.rs:122-133`) is platform-agnostic and returns two pointer-width payload types for `Tail`, `SystemV`, `PreserveAll` and `AppleAarch64`. Each ISA's own `exception_payload_regs` narrows this to the registers actually used on that target: on x86-64 (`isa/x64/abi.rs:979-987`), two payload values in `rax, rdx` only for `SystemV | Tail | PreserveAll` (`AppleAarch64` is unreachable on x86-64, every other variant gets the empty slice); on aarch64 (`isa/aarch64/abi.rs`, `PAYLOAD_REGS`), two payload values in `x0, x1` for `SystemV | Tail | PreserveAll | AppleAarch64`.
- **For cig: take.** By rule 2 (errors happen at the same place) and decision (d): CIR's `Try { body, catch }` names the handler; stage C (not built today) would emit one `try_call` per `CallBuiltin`, `CallUser`, `CallValue` or `CallMethod` under a `Try` scope, with the exception table naming the catch block as the tagged target and the normal block as the fallthrough. cig's error codes would become tag values (`E503`, `E515`, `E701` and the rest), and the payload registers would carry the error object. The step count, the open-tries list and the journal position would stay in cig's own runtime context (the pinned register or the vmctx, next entry), not in the exception payload. cig's form: one exception table per `Try`, with one tag per cig error class.
- **What would decide it.** Decided by rule 2 and the design in decision (d).
- **Feeds.** cig-compile#32; decision (d).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/ir/exception_table.rs` (`ExceptionTableData`, `InternalExceptionTableItem`, `BlockCall`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/call_conv.rs` (`exception_payload_types`, `supports_exceptions`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/aarch64/abi.rs` (`exception_payload_regs`, `PAYLOAD_REGS`); `wasmtime-v50.0.1/cranelift/codegen/src/machinst/buffer.rs` (`exception_handlers`); `cig-script/src/lower/cir/ir.rs` (`Try`).

### 10. Stack probes, frame pointers, and the pinned register

- **What it does, and why.** `enable_probestack` turns on stack-overflow probes for supported conventions; the probe is a call to a `__cranelift_probestack` function (`outline`) or inline code (`inline`) depending on `probestack_strategy`. `probestack_size_log2` defaults to 12 (4,096-byte pages): a frame larger than that is probed in page-sized increments. The x64 implementation (`X64ABIMachineSpec::gen_probestack`, `gen_probestack_unroll`, `gen_probestack_loop`) stores a zero into each probed page by decrementing SP page-by-page; aarch64 does the same with a `stur wzr` pattern.

  `preserve_frame_pointers` forces every function (including leaf functions) to push RBP and set it to SP, so a stack walker without a side table can still walk frames. `enable_pinned_reg` reserves `r15` on x86-64 (and `x28` on aarch64) out of the regalloc pool, callable through `get_pinned_reg` and `set_pinned_reg` IR instructions; the pinned register is neither callee-saved nor allocated and is "completely under the control of the end-user". The x64 `get_machine_env` (`isa/x64/abi.rs:875-883`) is call-conv agnostic: it returns the one `MachineEnv` built by `create_reg_env_systemv(enable_pinned_reg)` for every convention. With `enable_pinned_reg=true`, `r15` is omitted from both `preferred_regs_by_class` and `non_preferred_regs_by_class` (`isa/x64/abi.rs:1339-1343`), so regalloc cannot allocate it under any convention; `is_callee_save_systemv` also returns false for `r15` in that case (`isa/x64/abi.rs:1143`). Under `Tail` the comment "`r15` is reserved as a scratch register" at `isa/x64/abi.rs:1084` only explains why `r15` is skipped from `Tail`'s own eight-register return list; with `enable_pinned_reg` on, `r15` is not a scratch for anyone, it is the pinned register. The two settings are compatible.
- **For cig: take.** By rule 1 (burns never move) and rule 8 (reproducible, signable): stage C would turn `enable_probestack` on with `probestack_strategy=inline` (fewer symbols in the binary; a signed-binary gate prefers inline). It would turn `preserve_frame_pointers` on so the operator and a profiler can walk cig's stack without DWARF. The pinned register would be cig's runtime context: `r15` on x86-64 and `x28` on aarch64 holding a pointer to the current `cig_rt` state, and every runtime callback taking it as a hidden first argument. The step counter (`E515`) and the burn journal's open position would then be inline loads off this register, not globals.
- **What would decide it.** Not measured yet: `mandel.cig` with and without `enable_pinned_reg` (+register pressure), and the probe strategy's effect on a hot `fib.cig`, on the test machine.
- **Feeds.** cig-compile#32, #40; decisions (d), (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/meta/src/shared/settings.rs` (`enable_probestack`, `probestack_size_log2`, `probestack_strategy`, `preserve_frame_pointers`, `enable_pinned_reg`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/x64/abi.rs` (`gen_probestack_unroll`, `gen_probestack_loop`, `is_callee_save_systemv`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/aarch64/abi.rs` (`gen_probestack_unroll`, `gen_probestack_loop`); `cig-script/src/vm/mod.rs` (`Frame`).

### 11. regalloc2's input: the `Function` trait and `Operand`

- **What it does, and why.** The register allocator takes a client that implements `pub trait Function` in `src/lib.rs`: `num_insts`, `num_blocks`, `entry_block`, `block_insns`, `block_succs`, `block_preds`, `block_params`, `is_ret`, `is_branch`, `branch_blockparams`, `inst_operands`, `inst_clobbers`, `num_vregs`, `spillslot_size`, plus the optional `debug_value_labels`, `multi_spillslot_named_by_last_slot`, `allow_multiple_vreg_defs`, `is_block_cold`. The CFG must have no critical edges (`doc/GENERAL.md`), the entry block has an implicit predecessor, every block ends in a return or branch, and the IR must be SSA (every vreg defined exactly once, every use dominated by its def). An `Operand` is a bit-packed `u32` carrying a `VReg`, an `OperandConstraint` (`Any`, `Reg`, `Stack`, `FixedReg(PReg)`, `Reuse(usize)`, `Limit(u8)`), an `OperandKind` (`Def`, `Use`, `Mod`), and an `OperandPos` (`Early`, `Late`). Up to `2^21` vregs per function and `2^20` instructions per function, with 64 physical registers per class ("sufficient for the anticipated use-cases"); past these limits, the design doc recommends a simpler allocator. `inst_clobbers` reports a `PRegSet` of registers this instruction overwrites "arbitrarily, separately from the usual outputs": the file's own doc comment says "a clobber is equivalent to a late def of a fresh vreg that is not used anywhere else in the program, with a fixed-register constraint". The constructor `Operand::reg_use`, `reg_use_at_end`, `reg_def`, `reg_def_at_start`, `reg_temp` cover the shapes a lowering needs; the `Reuse(which)` constraint is the two-address machine-ISA idiom for `rax := rax + rcx` reusing the input.
- **For cig: take.** By rule 5 (identical behavior) and decision (e): Cranelift's `VCode` implements this trait, so stage C gets the input shape for free. cig-cherry needs the same trait for its JIT: a `Vcode` of its own, with operands and clobbers per lowered instruction. cig's form: stage C and cig-cherry share a common Vcode type that implements `regalloc2::Function`, so the allocator is pluggable. The `is_block_cold` hook is the cig-cherry side of the trait that CIR's structured blocks let it fill in deterministically (cig's block-cold set is `catch` blocks and the error-path branches of `MayRaise` instructions).
- **What would decide it.** Decided by rule 5.
- **Feeds.** cig-compile#32; decision (e).

### 12. Ion: the backtracking allocator

- **What it does, and why.** Ion is the default algorithm (`Algorithm::Ion` is `RegallocOptions`'s default). Its pipeline, documented in `doc/ION.md` and implemented across `src/ion/*.rs`: first, backward dataflow produces exact livein/liveout bitsets; a reverse scan over instructions produces live ranges keyed by `ProgPoint` (`inst << 1 | Before|After`); each range's vreg gets an initial bundle; bundles are merged across reuse-constraints and block parameters (`src/ion/merge.rs`); every bundle gets a `priority` (sum of range lengths) and a `weight` (uses-and-defs weighted by loop depth, sum of uses, with a scaling by `1 << 20` per loop level and divided by priority); bundles are processed off a max-heap.

  For each, the allocator probes physical registers in a hinted, randomized-offset order, picks the lowest-cost of {allocate, evict-and-retry, split-and-requeue}, and iterates until either the bundle is allocated or it reaches "minimal" size (one instruction), at which point its weight is "guaranteed to evict any non-minimal bundle". Termination: "bundles always get smaller, eviction only occurs when a bundle is strictly higher weight, and a minimal bundle has an extremely high weight". A "spill bundle" per spillset is a fallback that accepts a spillslot allocation and is processed in a second-chance pass. Design is explicitly influenced by SpiderMonkey's IonMonkey backtracking allocator.
- **For cig: take.** By rule 5 (identical behavior) and rule 8 (reproducible, signable): regalloc2 is deterministic for a given input and chosen algorithm; the heuristics are random but the random seed is derived from (bundle index, instruction index), not a clock, so re-runs produce identical output. cig would take this allocator as it is at `opt_level=speed` and `speed_and_size`, once stage C is built. Nothing in cig's rules tries to bound the allocator's time to a more aggressive limit than its own infinite-loop safeguard.
- **What would decide it.** Not measured yet: Ion's wall-clock cost on `orchestrate.cig` at stage C, on the test machine, against Fastalloc's cost.
- **Feeds.** cig-compile#32, #37; decision (e).
- **Read.** `regalloc2-v0.15.3/doc/ION.md` (`ProgPoint`, `live-range`, `bundle`, `spillset`, `priority`, `weight`, `probe`, `eviction`, `split`, `spill bundle`, `second-chance`); `regalloc2-v0.15.3/src/ion/data_structures.rs` (`Ctx`, `Env`); `regalloc2-v0.15.3/src/ion/liveranges.rs`; `regalloc2-v0.15.3/src/ion/merge.rs`; `regalloc2-v0.15.3/src/ion/process.rs`; `regalloc2-v0.15.3/src/ion/spill.rs`; `regalloc2-v0.15.3/src/ion/moves.rs`; `regalloc2-v0.15.3/src/ion/redundant_moves.rs`; `regalloc2-v0.15.3/src/ion/requirement.rs`.

### 13. Fastalloc, and the `regalloc_algorithm` setting that picks it

- **What it does, and why.** Fastalloc is `Algorithm::Fastalloc` in `RegallocOptions`; `doc/FASTALLOC.md` says it is "based on the reverse linear scan register allocation/SSRA algorithm" and is "made specifically for fast compile times". It walks blocks backward and instructions within each block backward. Per class it keeps an LRU of physical registers (`src/fastalloc/lru.rs`); `vreg_allocs` is the current allocation of each vreg; `live_vregs` is a doubly-linked list of currently live vregs; `available_pregs` is a tuple of two `PRegSet` for the "early" and "late" phases of the current instruction. For each instruction: reset `available_pregs` to all allocatable regs, assign fixed-register operands first, evict clobbers out of the "late" set, then process "late" operands (defs and uses) then "early" operands, inserting edits for any value whose current allocation does not fit. Every vreg gets a dedicated spillslot the first time it is spilled, and invariant 2 states "a virtual register that outlives the block it was defined in will be in its dedicated spillslot by the end of the block". `cranelift/codegen/src/machinst/compile.rs` reads `b.flags().regalloc_algorithm()` and maps `RegallocAlgorithm::Backtracking` to `Algorithm::Ion` and `RegallocAlgorithm::SinglePass` to `Algorithm::Fastalloc`; the flag is declared in `cranelift/codegen/meta/src/shared/settings.rs` under `regalloc_algorithm`, with SSA validation turned on when `debug_assertions` is on and `verbose_log` driven by `regalloc_verbose_logs`.
- **For cig: adapt.** By rule 10 (ahead of time by default) and rule 8 (reproducible, signable): Fastalloc is the right algorithm for `opt_level=none` (cig's `-O0` once stage C is built, and for cig-cherry's first warm-up tier), where allocation time matters more than code quality; its single-pass shape has a predictable upper bound on time (linear in instructions, modulo LRU updates), which is what cig-cherry would need for tight budgets. cig has no Cranelift dependency today and no `-O` level mapped to an allocator; stage C would wire its levels directly through the `regalloc_algorithm` flag: `-O0` to `single_pass`, `-O1`, `-O2`, `-O3` and `-Os` to `backtracking`. `--profile-use` and cig-cherry's tier-2 would use `backtracking` once the one-pass tier has warmed. cig would not add a knob of its own.
- **What would decide it.** Not measured yet: build time and code size of `orchestrate.cig` at each level, with each algorithm, on the test machine.
- **Feeds.** cig-compile#32, #37; decision (e).
- **Read.** `regalloc2-v0.15.3/doc/FASTALLOC.md` (`vreg_allocs`, `vreg_spillslots`, `live_vregs`, `lrus`, `available_pregs`, `num_available_registers`, `num_any_reg_operands`, `Reuse Operands`, `Branch Instructions`, `invariant`); `regalloc2-v0.15.3/src/fastalloc/mod.rs`; `regalloc2-v0.15.3/src/fastalloc/lru.rs`; `regalloc2-v0.15.3/src/fastalloc/vregset.rs`; `regalloc2-v0.15.3/src/fastalloc/iter.rs`; `wasmtime-v50.0.1/cranelift/codegen/src/machinst/compile.rs` (`RegallocAlgorithm`, `Backtracking`, `SinglePass`, `regalloc_algorithm`, `regalloc_verbose_logs`); `wasmtime-v50.0.1/cranelift/codegen/meta/src/shared/settings.rs` (`regalloc_algorithm`).

### 14. The symbolic checker: regalloc2 proves its own output

- **What it does, and why.** `regalloc2::checker::Checker` is a dataflow proof that an allocator's output preserves the input SSA's dataflow. The analysis lattice at each program point is `(Allocation -> set-of-vregs)`, the powerset of all virtual registers with subset-order; the join is set-intersection; the top value is the whole set `V`, the bottom is the empty set. The transfer functions are stated plainly in the file header: `Edit::Move` inserted by the allocator copies the source slot's value-set into the destination slot; a statement with allocated form `A_i := op A_j, A_k, ...` produces a singleton set `{V_i}` at `A_i` and removes `V_i` from every other allocation. After the fixpoint, at each operand the checker verifies that "the allocation for each op arg (input/use) contains the symbol corresponding to the original virtual register specified for this arg". `CheckerError` variants are `MissingAllocation`, `UnknownValueInAllocation`, `ConflictedValueInAllocation`, `IncorrectValueInAllocation`, `StackToStackMove`, and the rest. The sidebar in the file explicitly limits what it proves: "we only need to verify the programs that we produce, not arbitrary programs". Cranelift's `compile.rs` calls `Checker::new`, `Checker::prepare(&output)` and `Checker::run()` when `flags.regalloc_checker()` is on.
- **For cig: take.** By rule 5 (identical behavior) and rule 7 (verified bytecode, never rewritten): a regression gate the allocator itself runs is cheaper than a differential suite that catches its output downstream. cig would turn this on for every CI build and in `-Otest`, off in release. cig's form: once stage C is built, `cig-compile`'s CI pipeline would set `regalloc_checker=true` through the Cranelift `Flags`; the build gate is cranelift_codegen's own. The checker's domain (per-function, per-allocation) means it catches a corruption in a single function; cig's differential suite is still what catches a cross-function regression.
- **What would decide it.** Decided by rules 5 and 7.
- **Feeds.** cig-compile#32, #39; decisions (d), (e).
- **Read.** `regalloc2-v0.15.3/src/checker.rs` (`Checker`, `CheckerErrors`, `CheckerError`, `MissingAllocation`, `UnknownValueInAllocation`, `ConflictedValueInAllocation`, `prepare`, `run`); `wasmtime-v50.0.1/cranelift/codegen/src/machinst/compile.rs` (`regalloc_checker`); `regalloc2-v0.15.3/src/ssa.rs`.

### 15. Unwind info: one abstract prologue, two formats

- **What it does, and why.** `isa/unwind.rs` defines `UnwindInst`, a pseudo-instruction emitted by ABI code inline with the prologue: `PushFrameRegs { offset_upward_to_caller_sp }`, `DefineNewFrame { offset_upward_to_caller_sp, offset_downward_to_clobbers }`, `StackAlloc { size }`, `SaveReg { clobber_offset, reg }`, `RegStackOffset { clobber_offset, reg }`, `Aarch64SetPointerAuth { return_addresses }`.

### 18. JIT memory and W^X

- **What it does, and why.** `cranelift/jit/src/memory/` holds the two providers: `ArenaMemoryProvider` reserves one large range up front and sub-allocates within; `SystemMemoryProvider` requests pages from the OS per-definition.

  Both keep pages read-write while bytes are being written (`region::protect(.., region::Protection::READ_WRITE)`) and, once a batch is complete, flip them in place with `set_readable_and_executable`, which issues `mprotect` through the `region` crate and (on aarch64 when `BranchProtection::BTI` is requested) a second `mprotect` with `PROT_BTI` set. This is the entire mechanism: at no point is a page simultaneously writable and executable. The arena provider's `Segment::target_prot` records the eventual protection (`READ_EXECUTE` or `READ_WRITE`) so a mid-batch read can tell which bucket a byte belongs to.
- **For cig: take.** By rule 8 (no memory both writable and executable): the Cranelift JIT already implements cig's rule 8, in the exact shape cig needs. cig-cherry's loader (not built today) would use `cranelift-jit`'s memory providers directly, or would write its own that follow the same W-then-X contract. Stage C's output is an object file, not a JIT target, so this is applicable only to cig-cherry; but the mechanism to read is the same.
- **What would decide it.** Decided by rule 8.
- **Feeds.** cig-compile#32; decisions (e), (f).
- **Read.** `wasmtime-v50.0.1/cranelift/jit/src/memory/mod.rs` (`BranchProtection`, `set_readable_and_executable`, `JITMemoryProvider`, `finalize`); `wasmtime-v50.0.1/cranelift/jit/src/memory/arena.rs` (`ArenaMemoryProvider`, `Segment`, `target_prot`); `wasmtime-v50.0.1/cranelift/jit/src/memory/system.rs` (`SystemMemoryProvider`, `set_readable_and_executable`, `non_protected_allocations_iter`).

### 19. Hardening settings: Spectre, BTI, pointer authentication, NaN canonicalization

- **What it does, and why.** Cranelift's shared settings (`cranelift/codegen/meta/src/shared/settings.rs`) include three hardening flags on by default: `enable_heap_access_spectre_mitigation` ("uses a conditional move to ensure that when a heap access index is bounds-checked and a conditional branch is used for the out-of-bounds case, a misspeculation of that conditional branch will select an in-bounds index to load on the speculative path"), `enable_table_access_spectre_mitigation` (the same for tables), and `unwind_info`. `enable_nan_canonicalization` forces every NaN to a canonical value for deterministic WebAssembly computation; off by default.

  The aarch64 ISA settings (`cranelift/codegen/meta/src/isa/arm64.rs`) include `use_bti` (Branch Target Identification), `sign_return_address` and `sign_return_address_all` (ARMv8.3 pointer authentication with the A key), `sign_return_address_with_bkey` (switch to the B key), `has_pauth` ("enables the use of non-HINT instructions, but does not have an effect on code generation by itself"), and `use_csdb` (a speculation-barrier insert under Spectre mode).
- **For cig: take.** By rule 8 (reproducible, signable): stage C would turn `enable_nan_canonicalization` on (rule 4: floats are IEEE-exact and reproducible), `enable_heap_access_spectre_mitigation` and `enable_table_access_spectre_mitigation` on (default), and `preserve_frame_pointers` on (previous entry). On aarch64, `use_bti` and `sign_return_address` would be on, with the A key (B key only where the OS requires it). `enable_compact_unwind_abi` on for Apple targets. Each would be a one-line settings call; cig would not invent its own switches.
- **What would decide it.** Decided by rules 4 and 8. The code-size cost of `sign_return_address` is `Not measured yet:` on `orchestrate.cig` for aarch64, on the test machine.
- **Feeds.** cig-compile#32, #40, #41; decisions (d), (e).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/meta/src/shared/settings.rs` (`enable_heap_access_spectre_mitigation`, `enable_table_access_spectre_mitigation`, `enable_nan_canonicalization`, `preserve_frame_pointers`, `unwind_info`, `enable_compact_unwind_abi`); `wasmtime-v50.0.1/cranelift/codegen/meta/src/isa/arm64.rs` (`use_bti`, `sign_return_address`, `sign_return_address_all`, `sign_return_address_with_bkey`, `has_pauth`, `use_csdb`); `wasmtime-v50.0.1/cranelift/codegen/src/isa/aarch64/abi.rs` (`select_api_key`, `APIKey`).

### 20. Compile time: `timing` names every phase, `opt_level` is the gate

- **What it does, and why.** `cranelift/codegen/src/timing.rs` names every pass the compiler runs, each one a function that returns a timing token dropped at the end of the pass: `process_file`, `verifier`, `compile`, `flowgraph`, `domtree`, `loop_analysis`, `preopt`, `egraph`, `gvn`, `licm`, `unreachable_code`, `remove_constant_phis`, `vcode_lower`, `vcode_emit`, `vcode_emit_finish`, `regalloc`, `regalloc_checker`, `layout_renumber`, `canonicalize_nans`, `try_incremental_cache`, `store_incremental_cache`, `wasm_translate_module`, `wasm_translate_function`. The `PassTimes` struct accumulates total time per pass over a run and is printed through `take_current`. `opt_level` is the one knob that decides how much of this is run: `none` skips the egraph pass entirely (so the mid-end's `gvn`, `licm`, `egraph` do no work), `speed` and `speed_and_size` run everything. There is no `-O1` middle tier at Cranelift level. The regalloc algorithm is an independent setting (previous entry); the incremental compilation cache is yet another (behind the `incremental-cache` Cargo feature). A profiler implementation is pluggable: `set_thread_profiler` replaces the default accumulator.
- **For cig: take.** By rule 10 (ahead of time by default): once stage C is built, cig would wire `opt_level=none` to `-O0`, `speed` to `-O1` and `-O2`, `speed_and_size` to `-Os`, and `speed` to `-O3` (cig would do its own extra passes at CIR for `-O3`, which stage C cannot know about). The timing names would let `cig-compile --timing` display a per-pass breakdown that maps to Cranelift's `PassTimes`. cig's own CIR-level passes would appear under their own tokens; the Cranelift tokens are opaque to cig and reported verbatim.
- **What would decide it.** Not measured yet: `cig-compile --timing orchestrate.cig -O2` once stage C is built, on the test machine, with the per-pass percentages.
- **Feeds.** cig-compile#32, #37; decisions (e), (f).
- **Read.** `wasmtime-v50.0.1/cranelift/codegen/src/timing.rs` (`define_passes`, `Pass`, `PassTimes`, `vcode_lower`, `vcode_emit`, `vcode_emit_finish`, `regalloc`, `regalloc_checker`, `take_current`, `start_pass`, `set_thread_profiler`); `wasmtime-v50.0.1/cranelift/codegen/meta/src/shared/settings.rs` (`opt_level`, `enable_incremental_compilation_cache_checks`); `wasmtime-v50.0.1/cranelift/codegen/src/context.rs` (`compile`, `optimize`).

## For the issues

- **cig-compile#32 (stage C):** the back end would be used whole, with the knobs in the table above. cig has no Cranelift dependency today and no native code path. Decision (a)'s value size settles which convention fits in registers: a planned 16-byte value (two words) fits under `SystemV` with `enable_llvm_abi_extensions` (three return regs) or `Tail` (eight); today's 24-byte value needs `Tail` on x86-64; a one-word NaN-boxed value fits under plain `SystemV` (entry 7). The result convention for `MayRaise` (the raise is a thrown exception through `try_call`) would map to `ExceptionTableData` with one tag per cig error class (entry 9). Tail calls would land on `return_call` when caller and callee are both CIR functions (entry 8). The one knob cig would add at stage C that Cranelift does not already have is `cig_rt_budget_exhausted(span)`, an opaque skeleton call the lowering would emit per `StepSite` from CIR (entry 1).
- **cig-compile#37 (build speed):** the pass list Cranelift runs (names in `timing.rs`, entry 20) would be the ceiling cig pays per function at stage C, and `opt_level=none` with `Algorithm::Fastalloc` the floor (entry 13). Incremental compilation at the function level would be the lever: a change to one function invalidates only its stencil (the IR of the other functions, module-level relocations unchanged), and Cranelift's incremental cache (entry 16 of the first study, `incremental_cache.rs`) is the mechanism. `-O0` build time is entry 13's measurement.
- **cig-compile#39 (correctness at scale):** regalloc2's symbolic checker would be the one in-allocator gate (entry 14). The differential suite would stay at zero differences by re-running the oracle on the stage-C output and comparing per-program outputs; the checker would be an extra guard that catches an allocator bug before the differential does.
- **cig-compile#40 (hardening):** every flag cig would turn on is a setting Cranelift already defines (entry 19); none are custom, which would keep the gate narrow and cig's attack surface small.
- **cig-compile#41 (targets):** the trait abstraction (`ABIMachineSpec` and `MachineEnv`, entry 6) covers x86-64 and aarch64 without a per-target code change above the ISA layer; a riscv64 build would re-use the same shape (Cranelift already ships `isa/riscv64/`). The target triple selects the unwind format (entry 15), the ABI, and the register environment. cig's cross-build matrix would be the product of (`x86_64-linux`, `x86_64-windows`, `aarch64-linux`, `aarch64-darwin`) and (`speed`, `speed_and_size`), with the ISA-specific hardening flags set per target.

## Not settled

- Whether cig would use `CallConv::Tail` universally (eight return regs) or `SystemV` with `enable_llvm_abi_extensions` (three return regs, `rax, rdx, rcx`). This also depends on decision (a): a 24-byte or 16-byte value needs more registers than an 8-byte NaN-boxed value (entry 7). Settled by the measurement in entry 7 against the ABI stability needed by cig's crash-dump tooling (`Tail` is explicitly not ABI-stable except for exception-payload regs).
- Whether cig would emit `return_call` for every self-recursive call in tail position, only for a subset (cig-cherry would prefer never to tail-call out of a compiled region), or never. Settled by the measurement in entry 8.
- The share of stage C's per-function time regalloc takes at each level, which decides whether `Fastalloc` is the right default for `-O1`. Settled by entry 13.
- Whether the compile-time cache in cig's stage C keys at function level (Cranelift's `incremental_cache.rs`, out of scope for this study) or at CIR-module level (cig's existing `cig-compile/src/cache.rs`). The right answer is both, but which loses on a miss is not settled here.
- Whether cig-cherry would use `ArenaMemoryProvider` or `SystemMemoryProvider`: the first is larger-reservation and avoids per-call `mmap`, the second is simpler. Settled by cig-cherry's own perf study, which is not this one.
